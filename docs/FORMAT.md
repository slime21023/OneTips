# OneTips format 1

一個 Tips 專案發布一個 Agent Skill。Tip Markdown 是唯一內容來源；索引可重建，不手改。所有 Markdown 檔與設定使用 UTF-8，產生的檔案使用 LF。

```text
README.md
onetips.yaml
skills/<name>/SKILL.md
skills/<name>/INDEX.md
skills/<name>/references/<id>.md
```

README 用相對連結指向 `skills/<name>/INDEX.md`。對外安裝的是 `skills/<name>/`，不是整個專案。不用 Python、網路或原始 repo 就能閱讀安裝內容。skill 內的檔案連結不能指向安裝範圍之外。

## 設定 `onetips.yaml`

```yaml
format: 1
name: acme-tips
domain: Acme SDK
subjects:
  acme-sdk: Acme SDK
categories:
  - id: networking
    title: Networking
sections:
  when: When to Use
  approach: Recommended Approach
  pitfalls: Pitfalls
  checklist: 檢查清單
snippets:
  python:
    ext: py
    compile: python -m py_compile {file}
    test: python {file}
    timeout: 120
```

- `format` 是整數 `1`。`name` 必須是 skill 資料夾名稱；它與 Tip ID 都是由小寫 ASCII 英文和數字組成、以單個連字號分隔的可攜名稱，長度 1–64，不用 Windows 保留名稱。
- `subjects` 是適用版本主體 ID 到顯示名的映射，可為空。`categories` 是依輸出順序排列的非空清單，類別 ID 不得重複；主體及分類 ID 都用 kebab-case。
- `sections` 必須指定 `when`、`approach`、`pitfalls`、`checklist` 四個鍵。標題可在地化，但須互異、非空、單行且不以 `#` 開始或結尾。顯示名與分類標題為非空單行文字。
- 可省略 `snippets`。它以 fence 語言標籤為鍵，`ext` 只接受 ASCII 字母與數字（不含點），`timeout` 是正整數秒數，預設 120。`compile`、`test` 分別為選用的 shell 指令；只有 `onetips snippets` 會執行它們。

## Tip

在 `references/` 直接放置 `<id>.md`，一篇只解決一個問題。不在 front matter 重複寫標題。

````markdown
---
id: retry-with-backoff
summary: Cap retry attempts and delay for transient failures.
category: networking
tags: [retry, timeout]
related: []
applies_to:
  acme-sdk: '>=2.0 <3.0'
---
# Limit transient retries

## When to Use

The operation can safely be retried after a transient failure.

## Recommended Approach

Use both a maximum number of attempts and a delay limit.

```python status=tested
limit = 4
assert limit > 0
```

## Pitfalls

Do not retry failures that are permanent.

## 檢查清單

- [ ] Limit both attempts and delay.
````

必填欄位為 `id`（同檔名且全專案唯一）、`summary`（1–200 字元、單行）、`category`（設定中定義的 ID）、`tags`（非空 kebab-case 清單）、`applies_to`（版本主體至非空版本字串的映射，可為空）。`*` 表示不限定該主體的版本；OneTips 不解譯範圍。`related` 可省略；若提供，只能列出存在的其他 Tip ID，不可指向自身。可用 `x-*` 放擴充資料。發布後不可重用 ID。

第一個非空區塊是唯一的 H1；四個設定 H2 各出現一次，依 `when` → `approach` → `pitfalls` → `checklist`。可加其他 H2 或較低階標題。檢查清單至少有一個有文字的 Markdown task-list 項目。圍欄中的標題或清單不是章節與檢查項目。`new` 產生未填完的草稿；發布前須補齊。

## 程式碼片段

Fence 的第一個詞是必填語言標籤。可另外指定一個 `status=unverified|compiled|tested`；省略就是 `unverified`。超過 60 行會告警。

- `unverified` 不執行。
- `compiled` 執行該語言的 `compile`。
- `tested` 先執行選用的 `compile`，成功後執行必填的 `test`。

每段獨立擷取到暫存檔。指令從專案根執行，`{file}`、`{dir}` 以獨立且未加引號的參數書寫，分別代表擷取檔與其目錄。成功是 exit 0；缺指令、逾時、非零結束均為失敗。**只對信任的來源執行 `snippets`**：命令和擷取程式碼不是在沙箱內執行。`check`、`verify`、查詢、安裝都不執行範例。

## 連結與安裝

相對檔案連結須存在，Markdown 片段指向 GitHub 標題錨點或 Markdown 中明確的 `<a>`。檢查 link/image 的區域路徑，不請求遠端 URL。README 只導覽專案內檔案；skill 只導覽 skill 內檔案。不要引用安裝時會略過的檔案、資料夾或範圍外符號連結。`onetips verify <skill-dir>` 在不讀設定的前提下檢查已安裝內容；成功時輸出與 skills lock v2 相容的雜湊。

## 產生的 `INDEX.md`

索引首行為 ``<!-- Generated by `onetips index`. Do not edit by hand. -->``，再接 `# <domain> Tips — Index`、空行、``N tips. Each row links to one tip in `references/`.``、空行與 `### Sections`。章節用 ``- `<key>`: <title>`` 列出四個對照，順序同設定，即使沒有 Tip 也輸出。

每個非空分類以 `## <category-id> — <title>` 開頭。表格使用固定欄名和順序：`ID`、`Title`、`Summary`、`Tags`、`Applies to`、`Snippets`。分類使用設定順序，資料列依 ID 的 ASCII 順序；ID 欄用 `[<id>](references/<id>.md)`，標籤用逗號加空格分隔，版本顯示 `subject range`，以分號加空格分隔。片段欄格式 `tested N, compiled N, unverified N`。顯示文字中的 Markdown 控制字元以實體轉義，表格中的 pipe 轉為 `\|`。檔尾有一個 LF；同樣輸入產出同樣位元組。

## `SKILL.md`

YAML front matter 必須含 `name`（等於目錄名）、`description`（非空且至多 1024 字元）；可用字串映射 `metadata` 宣告 `onetips-format: '1'`。本文連到 `INDEX.md`，先要求確認目標專案的版本與慣例，再找 Tip。只讀所需章節或片段；把程式碼當參考、checklist 當審查依據，不覆蓋專案決策。索引指到缺檔時回報安裝不完整。可使用 OneTips 查詢指令，但不可把工具存在當作閱讀前提。超過 500 行會告警。
